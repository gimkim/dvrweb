# WebRTC over existing web port feasibility

User asks whether WebRTC media can use the main HTTPS port/path as a proxy to internal8189, avoiding direct Internet exposure of8189. Verified current source: same-origin authenticated signaling route already proxies to loopback18889; ICE media listens UDP/TCP8189. Official MediaMTX configuration distinguishes HTTPS handshake from encrypted peer media; normal HTTP path proxy cannot transport ICE/DTLS-SRTP.

Options: external UDP443 forwarded to internal UDP8189 shares the number with TCP HTTPS but still exposes peer media; TURN/TLS443 can relay media and keep8189 private, but sharing existing TCP443/IP requires a front protocol/TLS multiplexer and suitable hostname/routing, not an IIS path rule. Existing fMP4 fallback already sends media through authenticated HTTPS path. No network/server configuration/code changed or deployed; no browser tests. No router/TURN setup assumed authorized or complete from a feasibility question.
